SORUN 1: PULL-TO-REFRESH GOSTERGESI TAKILI KALIYOR
====================================================

KULLANICI TANIMI:
Sayfayi yuklemek icin asagi dogru parmakla cekildiginde yukaridan
bir yenileme simgesi (spinner/loading indicator) cikiyor. Ancak
fazla cekildiginde veya tam yerinde birakildiginda bu gosterge
yerinde sabitlenip kaliyor, geri yukari gitmiyor.

MEVCUT DURUM:
- Compose PullToRefreshBox kullaniyorsunuz (View sistemi degil)
- refreshScope.launch + delay(5000) ile 5 saniyelik zaman asimi
  eklendi, en gec 5 saniyede gosterge kayboluyor
- Bu bir BAND-AID cozum, kok neden hala cozulmedi

KOK NEDEN (MUTLAKA BULUNMALI):
5 saniyelik timeout bir ise yaramaz: isRefreshing = false'in
NORMAL AKISTA hicbir zaman cagrilmamasi, su sorunlardan birini
isaret eder:

1. ViewModel'deki refresh fonksiyonu hic tamamlanmiyor
   - Firestore sorgusu sonsuza dek askida (canli listener?)
   - viewModelScope iptal edilmis (lifecycle kapali)
   - Coroutine exception sessizce yutuluyor

2. refreshState StateFlow'u UI'a iletilmiyor
   - StateFlow .collect() cagrilmiyor veya scope kapali
   - State bir kez Refreshing'te kalip Idle'a donmuyor

3. PullToRefreshBox'un isRefreshing parametresine yanlis
   state baglanmis. Ornegin Scaffold ile catisma.

COZUM (dogru yontem):
  // 5 saniyelik timeout'u KALDIR. Onun yerine:
  viewModelScope.launch {
      isRefreshing = true
      try {
          val result = withTimeout(15_000L) {  // gercekci timeout
              repo.refreshData()
          }
          // basarili
      } catch (e: TimeoutCancellationException) {
          Log.e("Refresh", "Zaman asimi")
          // kullaniciya bildir
      } catch (e: Exception) {
          Log.e("Refresh", "Hata: ${e.message}")
      } finally {
          isRefreshing = false  // HER DURUMDA CALISIR
      }
  }

BENIM YORUMUM (Deep):
delay(5000) cozum degil, semptomu gizliyor. Asil sorun su:
refreshScope.launch icindeki islem hic bir sekilde
"tamamlandi" sinyali gondermiyor. Firestore'dan veri cekme
isleminin sonunda .addOnCompleteListener veya suspend
fonksiyonun await() ile bitip bitmedigini kontrol et.
Eger Firestore sorgusu canli bir listener (onSnapshot) ile
yapiliyorsa, o SONSUZA KADAR acik kalir ve suspend olmaz.
Refresh icin get() kullan (tek seferlik), onSnapshot degil.

SORUN 2: BILGISAYAR & MOBIL STORY SISTEMI ENTEGRASYONU
========================================================

HEDEF:
Bilgisayar surumunde (Electron/JS) atilan story'ler mobil
surumde (Android Native) goruntulenebilmeli. Mobildeki story
arabirimi bilgisayardakiyle birebir ayni calismali:
- Story bar (kullanici profili + arkadaslarin story'leri)
- Story viewer (text/image/video goruntuleme)
- Viewed/unviewed takibi (halka renklendirmesi)

--- VERI MODELI (Firestore) ---

Desktop story.js'deki veri yapisi (Firestore'daki 'stories'
koleksiyonunda saklaniyor):

  /stories/{storyId}  (Firestore dokumani)
  {
    authorId:   String,  // Firebase Auth UID
    authorName: String,  // Gosterim adi
    authorAvatar: String,// data URL veya Firebase Storage URL
    authorColor: String, // #818cf8 gibi hex renk
    type:       String,  // "text" | "image" | "video"
    createdAt:  Timestamp, // firebase.firestore.FieldValue.serverTimestamp()
    expiresAt:  Timestamp, // olusturma + 24 saat
    viewers:    [String],  // izleyen kullanici UID'leri
    // type === "text" icin:
    text:       String,   // en fazla 500 karakter
    bgColor:    String,   // #818cf8
    fontFamily: String,   // "sans" | "serif" | "mono" | "rounded"
    // type === "image" || type === "video" icin:
    mediaUrl:   String,   // Firebase Storage URL (veya fallback data URL)
    caption:    String    // en fazla 200 karakter
  }

ExpiresAt: olusturma ani + 24 saat. 24 saatten eski story'ler
Firestore listener tarafindan filtrelenir ve gosterilmez.

--- YAPILACAKLAR (MOBIL TARAFI) ---

1. FIRESTORE VERI OKUMA (STORY LISTENER)
   Desktop'taki fbListenStories() fonksiyonunun Android karsiligi:
   - Kendi UID + arkadas UID'lerini al
   - 10'arli batch'ler halinde Firestore'u dinle (in operatoru
     maksimum 10 deger alir)
   - Sorgu: .where('authorId', 'in', batchIds)
            .where('expiresAt', '>', Timestamp.now())
   - onSnapshot ile canli dinle
   - Gelen her yeni/guncellenen story'yi local listeye ekle
   - Silinen story'leri listeden cikar
   - Story'leri expiresAt'e gore sirala
   - View status'unu local'de (SharedPreferences vb.) sakla

   FIRESTORE QUERY ORNEGI (Kotlin):
   ```kotlin
   val myUid = FirebaseAuth.getInstance().currentUser?.uid ?: return
   val friendIds = getFriendIds() + myUid

   for (i in friendIds.indices step 10) {
       val batch = friendIds.subList(i, minOf(i + 10, friendIds.size))
       FirebaseFirestore.getInstance()
           .collection("stories")
           .whereIn("authorId", batch)
           .whereGreaterThan("expiresAt", Timestamp.now())
           .addSnapshotListener { snapshot, error ->
               snapshot?.documentChanges?.forEach { change ->
                   when (change.type) {
                       DocumentChange.Type.ADDED -> addStory(change.document)
                       DocumentChange.Type.MODIFIED -> updateStory(change.document)
                       DocumentChange.Type.REMOVED -> removeStory(change.document)
                   }
               }
               updateStoryBar()
           }
   }
   ```

4. STORY RING / HALKA CIzIMI
   Desktop'taki makeStoryRingSvg() fonksiyonunun Android karsiligi:
   - Canvas uzerine cizilebilir custom View
   - Veya SVG'den PNG'ye donusturulebilir
   - Iki halka: gri (base) + mavi (gorulmemis segmentler)

   ```kotlin
   class StoryRingView @JvmOverloads constructor(
       context: Context, attrs: AttributeSet? = null
   ) : View(context, attrs) {

       private val grayPaint = Paint().apply {
           color = Color.GRAY
           style = Paint.Style.STROKE
           strokeWidth = 3.dpToPx()
           strokeCap = Paint.Cap.ROUND
       }
       private val bluePaint = Paint().apply {
           color = Color.parseColor("#3b82f6")
           style = Paint.Style.STROKE
           strokeWidth = 3.dpToPx()
           strokeCap = Paint.Cap.ROUND
       }

       private var total = 0
       private var viewed = 0

       fun setSegments(total: Int, viewed: Int) {
           this.total = total
           this.viewed = viewed
           invalidate()
       }

       override fun onDraw(canvas: Canvas) {
           super.onDraw(canvas)
           if (total == 0) return
           val cx = width / 2f
           val cy = height / 2f
           val r = minOf(cx, cy) - 4f
           val circ = 2 * Math.PI.toFloat() * r
           val gapAngle = if (total <= 1) 0f else 8f
           val gapArc = circ * gapAngle / 360f
           val segLen = (circ - total * gapArc) / total

           // once gri halka (tum segmentler)
           val grayPath = Path()
           for (i in 0 until total) {
               val startAngle = i * (segLen + gapArc) / circ * 360f - 90f
               val sweepAngle = segLen / circ * 360f
               grayPath.addArc(cx - r, cy - r, cx + r, cy + r, startAngle, sweepAngle)
           }
           canvas.drawPath(grayPath, grayPaint)

           // sonra mavi halka (sadece gorulmemis segmentler)
           if (viewed < total) {
               val bluePath = Path()
               for (i in viewed until total) {
                   val startAngle = i * (segLen + gapArc) / circ * 360f - 90f
                   val sweepAngle = segLen / circ * 360f
                   bluePath.addArc(cx - r, cy - r, cx + r, cy + r, startAngle, sweepAngle)
               }
               canvas.drawPath(bluePath, bluePaint)
           }
       }
   }
   ```

8. HATA DURUMLARI & COZUMLERI
   - Yetki hatasi (Firestore security rules): stories koleksiyonu
     icin read/write kurallari hem desktop hem mobil icin dogru
     ayarlanmali:
     match /stories/{storyId} {
       allow read: if request.auth != null
         && (resource.data.authorId == request.auth.uid
             || request.auth.uid in resource.data.viewers);
       allow create: if request.auth != null
         && request.resource.data.authorId == request.auth.uid;
       allow update: if request.auth != null
         && resource.data.authorId == request.auth.uid;
       allow delete: if request.auth != null
         && resource.data.authorId == request.auth.uid;
     }
   - Media URL 404: Firebase Storage rules da eklenmeli:
     match /stories/{userId}/{allPaths=**} {
       allow write: if request.auth != null
         && request.auth.uid == userId;
       allow read: if request.auth != null;
     }
   - Story suresi dolmus (24 saat): expiresAt filtresi ile
     otomatik elenir. Gorev zamanlayici ile silinebilir.
   - Gorsel yuklenemezse (Coil/Glide hatasi): fallback olarak
     yazarin bas harfini goster.

10. EK: ENTEGRASYONUN ONUNDAKI GIZLI ENGELLER (MUTLAKA KONTROL EDIN)
    Asagidaki maddeler "her sey calisiyor" denmesine ragmen
    story'lerin mobilde goruntulenememesinin GERCEK sebepleridir:

    a) FIRESTORE COMPOSITE INDEX GEREKIYOR
       Sorgu: .whereIn("authorId", batch).whereGreaterThan("expiresAt", now)
       Bu sorgu icin Firestore'un su index'e ihtiyaci var:
         Collection: stories
         Fields: authorId ARRAY, expiresAt DESC
       Eger index yoksa sorgu HATA verir. Hata genelde
       Firebase konsolunda link olarak gelir, ama catch
       edilip yutuluyorsa gorulmez.
       KONTROL: Firebase Console > Firestore > Indexes >
                "stories" koleksiyonunda authorId+expiresAt
                index'i var mi?

    b) DESKTOP'TA HIC STORY URETILEMEMIS OLABILIR
       Desktop fbCreateStory() (story.js:130) hata durumunda
       null doner ve sessizce yutulur:
         } catch (e) {
           console.error('createStory error:', e);
           return null;
         }
       Kullanici daha once "Missing or insufficient permissions"
       hatasi aliyordu (konsolda goruldu). Bu demektir ki
       desktop'tan Firestore'a hic story yazilamamis olabilir.
       Yani Firestore'da hic story dokumani YOK.
       Mobil okumaya calissa da okuyacak bir sey bulamaz.
       KONTROL: Firebase Console > Firestore > stories
                koleksiyonunda dokuman var mi? Eger bossa
                once desktop'tan rules fix'lenip story
                olusturulmali.

    c) MOBIL'DEKI QUERY ILE DESKTOPTAKI QUERY UYUMSUZ OLABILIR
       Desktop fbListenStories() sunu kullanir:
         .where('expiresAt', '>', firebase.firestore.Timestamp.fromMillis(storyNow()))
       Mobilde:
         .whereGreaterThan("expiresAt", Timestamp.now())
       Bu ikisi esit olmali. ANCAK:
       - Desktop'ta storyNow() = Date.now()
       - Mobilde Timestamp.now() = System.currentTimeMillis()
       Eger cihaz saatleri farkliysa veya Timestamp precision
       farkliysa eslesmeyebilir.
       KONTROL: Mobil cihaz ile bilgisayar saatinin ayni olup
                olmadigini kontrol et. expiresAt'in desktop'ta
                nasil kaydedildigini gor (serverTimestamp + 24h).

    d) "Yapilacak bir sey yok" DIYORSA
       Firestore rules guncellendikten SONRA rules'un Firebase
       Console'a KAYDEDILDIGINE emin ol. Bazen "yayimla"
       butonuna basmayi unutuyoruz. Ayrica degisikliklerin
       etkili olmasi icin 1-2 dakika gerekebilir.
       KONTROL: Firebase Console > Firestore > Rules >
                En ustte "Published" tarihi gorunuyor mu?
                Story icin allow read, allow create izni var mi?

    e) LISTENER CANLI MI?
       listenStories() cagrilmis olabilir ama hata callback'inde
       sessizce yutuluyordur. addSnapshotListener'in hata
       parametresini log'a bas:
         .addSnapshotListener { snapshot, error ->
             if (error != null) {
                 Log.e("Stories", "Listener hatasi: ${error.message}")
                 return@addSnapshotListener
             }
             ...
         }
       KONTROL: Logcat'te "Stories" tag'inde hata var mi?
